# Physical-device acceptance

Automated compilation/tests are separate from these hardware checks. Record actual results and timings before marking a device ready.

| Check | Procedure | Actual result / measurement |
| --- | --- | --- |
| Fresh install | Continue with Google on laptop and phone using the same email; verify browser returns to IRIS; grant both permissions and start | Phone Google sign-in/return confirmed by user; media check pending |
| Clay UI | Check mint background, raised rounded cards and shaded teal/honey buttons; inspect setup, camera waiting view and Controls at large Android font size | Pending |
| Account isolation | Use a second laptop account; verify it cannot see this phone or send it speech | Automated relay checks pass; physical test pending |
| Account revocation | Sign out on either device and verify its connection closes while the other remains signed in. Revoke the phone's parent auth session and verify it stops within 15 seconds. | Automated checks pass; physical test pending |
| OAuth recovery | Cancel Google sign-in, retry, and test Android process recreation while browser is open; reject expired, wrong-state and replayed returns | Automated PKCE/callback tests pass; physical recovery check pending |
| Camera and audio | Phone video/audio arrives in the main web console; wave to measure delay | Pending; target video start <3 s and delay <0.5 s |
| Frontend camera on phone | Connect the main console, grant camera access, verify webcam preview and main phone video; disconnect/disable the frontend camera and verify waiting state | Pending |
| Speech playback | Send queued speech twice; hear loudspeaker in a noisy room; verify one started/finished pair per ID | Pending; target first playback <1 s |
| Conversation | Say a sentence; verify real backend transcript and confirmed reply | Pending; target speech-to-cards <3 s |
| No self-hearing | Speak several replies and check no upload from their playback or tail | Pending |
| Noise/manual capture | Play crowd noise; test Silero and tap-to-talk | Pending |
| Media fallback | Force JPEG; check frames in the main console and continued WAV uploads; retry WebRTC | Pending |
| STT fallback | Select Android STT; tap; check transcript; exit mode and restore RTC | Pending; availability depends on phone |
| Reconnect | Wi-Fi off for 5 s and back; verify WS/video recovery | Pending |
| Foreground lifecycle | Home/lock screen; verify sensors/media released and robot disarmed; restart manually | Pending |
| Long run | Ten minutes: screen stays on, feed and listening remain usable, thermal/battery behavior | Pending |
| Robot readiness | Wheels raised: upright stationary calibration; full ESP status; valid authorized session; explicit Enable | Pending |
| Wheel signs | Forward/backward, left/right, and speed-zero/STOP | Pending |
| Gyro feedback | Disturb heading in forward/reverse; renew held commands without losing target; turns do not fight heading hold | Pending; tune gains on this chassis |
| Input expiry | Stop publishing intentions while broker remains connected | Pending; measure physical stopping time |
| Faults | Stale sensors/status, revoked/expired session, broker loss, background, bump and tilt | Pending; each disarms and needs explicit enable |
| Replay rejection | Unsigned, edited, retained, duplicate, old, future, wrong-session and wrong-device intentions do not start or extend driving | Pending |
| Password mismatch | Incorrect ESP password has no motor effect; publish success does not prove execution | Pending |

Start motor tests with wheels raised and an accessible physical power stop. Verify the fixed portrait mount and robot-yaw sign before tuning gains. The current ESP has no obstacle or desk-edge detector.

For the demo, record one real end-to-end backup run, collect measured latency/stop/navigation results, choose patient/friend roles and exact sentences, and rehearse the sequence three times. Pitch slides and recorded footage require those real measurements and human/device participation; they are not generated by the app.
